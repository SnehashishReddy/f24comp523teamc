Ideal Testing Plan

1. Unit Tests

  • Write unit tests for individual functions:
    • extract_input
    • generate_master_match_df
    • create_match_entry
    • calculate_probability
    • perform_ilp_matching
    • convert_to_custom_json
  • Use a testing framework (Jest or Mocha).
  • Mock dependencies and external services.

2. Manual Testing

  • Test the UI for different user roles (e.g., students, faculty, administrators).
  • Verify form submissions and data display.
  • Check responsiveness on different devices and browsers.
  • Test error handling and edge cases.

3. Functional Testing

a. Manual Testing:

  • Verify the end-to-end flow of the matching process.
  • Test different scenarios with various input combinations.
  • Validate output formats and content.

b. Automated Tests using Firebase Test Suite:

  • Write integration tests using the Firebase Test SDK.
  • Test authentication flows.
  • Verify Firestore read/write operations.
  • Test Cloud Functions triggers and responses.

4. Integration Testing

a. Manual Testing:

  • Test the entire workflow from user input to final matching results.
  • Verify data consistency across different parts of the system.

b. Automated Testing:

  • Create a test dataset based on previous year's data.
  • Write automated tests to verify correct generation of the master match DataFrame.
  • Compare algorithm output with expected results from previous years.
  • Test edge cases and various input scenarios.

5. Performance Testing

  • Test the system with a large number of faculty and student preferences.
  • Measure response times and resource usage.
  • Identify and optimize bottlenecks in the matching algorithm.

6. Security Testing

  • Verify proper authentication and authorization.
  • Test for common vulnerabilities (e.g., injection attacks, XSS).
  • Ensure data privacy and proper handling of sensitive information.

7. Usability Testing

  • Conduct user acceptance testing with actual faculty and students.
  • Gather feedback on the user interface and overall experience.

8. Regression Testing

  • After each significant change or bug fix, run a suite of automated tests to ensure no new issues are introduced.

9. Load Testing

  • Simulate concurrent users submitting preferences and requesting matches.
  • Verify system stability under heavy load.

10. Error Handling and Recovery Testing

  • Test system behavior with invalid inputs.
  • Verify proper error messages and logging.
  • Test recovery procedures in case of system failures.
